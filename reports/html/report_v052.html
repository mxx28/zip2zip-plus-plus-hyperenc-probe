zip2zip-core · v0.52 (no-residual) weight probe · 2026-07-24

Inside a v0.52 hyper-token's vector: the output encoder reads the head, the input encoder rises toward the tail

Question: for the no-residual v0.52 model, which base token does a hyper-token's embedding resemble, and do the output (scoring) and input (embedding) encoders divide the labor? Same four steps as before, on v0.52's own numbers.

① Raw similarity to each base token (no ruler removed) ② Prove a shared "ruler" vector exists ③ Remove the ruler, re-measure ④ Causal minimal pairs: change head vs tail
What "no-residual" means here. v0.52 sets no_encoder_residual, so the final vector is the encoder's own output without adding the first base token back (E = encoder_out, not tok_emb[t1] + encoder_out). So what you see below is the learned encoder behavior directly — nothing is propped up by a residual. Everything else (untied / flat / 2-layer / 3072 / digit-safe / step 8000) matches v0.5.

Bottom line (v0.52)

OUTPUT = prefix-sensitive (reads the head): changing the first token dominates; and here it shows a graded decay (t1 > t2 > t3).
INPUT = distributed, weighted toward the tail: it draws on all base tokens but its similarity rises toward the last token.

Because v0.52 has no residual, the split comes purely from the learned encoders. Output still reads the head (change-first 3.3× change-last at K=4), but milder and more graded than the residual model; input, with no residual propping up the first token, tilts clearly toward the tail.

⑥Why this makes sense

OUTPUT reads the head. It scores "should I emit this whole merge H", logit = hidden · E_out(H). Emitting H means committing to start with its first token, so the head defines the candidate; later tokens taper off in influence.
INPUT rises toward the tail. It replaces the whole merge H in the decoder stream, which must continue from H's last token — so the ending carries the most weight for what comes next, while it still draws on the full span.

⑦Verdict

✓

output = prefix form: confirmed, and graded. Changing the first token affects the embedding 1.8–3.3× more than the last; the per-position signal tapers (t1 > t2 > t3). Without the residual, this is entirely the learned encoder.

✓

input = holistic, tail-weighted. It uses all base tokens but similarity and sensitivity both rise toward the last token (ratio 0.33 at K=4). With no residual propping up the head, the tail lean is cleaner than in the residual model.

!

Output still collapses (99.7% shared ruler). Removing the residual did not fix it — the collapse lives in the output encoder itself, and its per-merge discriminative signal is small. Likely under-utilization (hyper-tokens are a minority of output positions → weak gradient), worth checking directly.

⑧Implications

  • Even without the residual, the output side is dominated by a shared ruler and keyed on the first token — putting a hierarchical encoder there still targets a role that reads mostly the head. Consistent with the observed lack of clear gain from hierarchical.
  • The input side genuinely uses the full sequence and leans toward the tail — the better-motivated place for a hierarchical / sequential encoder if trying one.
  • Higher priority: diagnose the output collapse (log loss / grad-norm separately for base-token vs hyper-token output positions).

⑨Method & limitations

  • Measured on v0.52's final vector = encoder output (no residual, as the model uses it). Step ① uses raw cosine; ②③④ compare after subtracting the proven shared ruler.
  • Controls: ordinary-token baseline and a random-init encoder confirm the findings are learned.
  • Single checkpoint (v0.52, 8000 steps), single corpus. Strong evidence, not a final verdict.
