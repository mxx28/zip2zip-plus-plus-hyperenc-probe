Inside a hyper-token's vector: the output encoder reads the head, the input encoder is more uniform (uses the whole merge)

Question: a hyper-token is a merge of several base tokens — which of them does its embedding actually resemble? Do the output (scoring) and input (embedding) encoders divide the labor? Four steps make it clear.

① Raw similarity to each base token (no ruler removed) ② Prove a shared "ruler" vector exists ③ Remove the ruler, re-measure ④ Causal minimal pairs: change head vs tail
checkpoint: untied v0.5 / step_8000 both encoders identical arch (flat / bidirectional / mean-pool) forward re-impl max|Δ|=0 real English n-grams (K=2/3/4, ~1140 total)

Bottom line

OUTPUT = prefix-sensitive (reads the head): change the first token → the embedding changes drastically; change the last token → almost nothing (9× gap at K=4).
INPUT = more uniform (uses the whole merge): its content is spread fairly evenly across all base tokens, not governed by any single position — head and tail both prominent, at most a mild lean toward the ending.

The prefix hypothesis clearly holds for output; input is the opposite — it has no single dominant position. This is functionally sensible: output scores "should I emit this whole merge" = committing to start with the first token; the input embedding must represent the whole merged span so the decoder can continue, so it draws on all the tokens fairly evenly.

②Why output resembles none of its words: a shared "ruler" vector exists

Hypothesis: nearly all of each output hyper-token vector is a direction everyone shares (a ruler) that pushes them all to the same place, so the raw cosine with any specific base token gets diluted to ≈0. Not an assumption — provable, with two controls:

Decisive on the OUTPUT side: each output hyper-token's cosine with the global mean is 0.998 (even the least-aligned is 0.996) — i.e. they are almost the same vector, differing by only ~0.4%. This ruler is hyper-token-specific (ordinary tokens only 0.27) and learned (random-init only 0.63). On the INPUT side it's moderate (46%); more than half of each vector is still its own content.
This explains the oddity in ①: the output vector is 99.6% the shared ruler, and the ruler points at no particular base token, so every raw cosine is ≈0.

⑥Why this makes sense

OUTPUT reads the head. It is the scoring key for "should I emit this whole merge H", logit = hidden · E_out(H). Choosing to emit H means committing to start with its first token — so the first token defines what this candidate is; the rest are fixed by the codebook and barely affect whether to start.
INPUT uses the whole merge. It is the embedding fed into the decoder in place of the whole merge H, and must represent H's full content for what follows — so it draws on all base tokens fairly evenly (head and tail both prominent); unlike output, it has no single dominant position.

⑦Verdict on the hypothesis

✓

output = prefix form: confirmed. Changing the first base token affects the output embedding 3–9× more than changing the last, and the gap widens with length. Output's identity is set by the head.

✓

input = holistic: confirmed. It draws on all base tokens fairly evenly (every position positive, head and tail near-equal, content grows with length), with no single dominant position; the causal test shows a mild sensitivity to the ending, but nothing like output's extreme focus on the head — so it is a fairly uniform holistic representation, not a clean suffix reader.

✗

"graded prefix decay" (t1>t2>t3 tapering): not supported. Output is a spike on the first token with the rest ≈0, not a smooth decay; the middle positions carry no gradient.

⑧Implications for the experiment

  • Output's identity is set almost entirely by the first token, with the rest collapsed into the shared ruler — so putting a hierarchical (step-by-step over all subtokens) encoder on the output side bolts heavy sequence machinery onto a role that only reads the head. Doubtful payoff.
  • The side actually using the full sequence (drawing on all tokens fairly evenly) is input; if hierarchical helps anywhere, "hierarchical input + flat output" is better motivated than the reverse.
  • Higher priority: figure out why the output side collapses so extremely (99.6% shared ruler). It may be an under-training / under-utilization signal (hyper-tokens are a minority of output positions → weak gradient). Suggest logging loss / grad-norm separately for base-token vs hyper-token output positions during training.

⑨Method & limitations

  • Everything is measured on the final vector (residual included, the one the model uses). Step ① uses raw cosine; ②③④ compare after subtracting the proven shared ruler (the difference E₁−E₂ is unchanged by subtracting the mean; cosine similarity is not, hence the subtraction).
  • Controls: an ordinary-token baseline and a random-init encoder, confirming the findings are learned, not artifacts of architecture or embedding geometry.
  • Single checkpoint (v0.5, 8000 steps), single corpus. Strong evidence, not a final verdict; the hardest next test is using real decoder hidden states to check whether H's score tracks the first token's score.
